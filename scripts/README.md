# Скрипты

Операционные скрипты сайта. Запускаются вручную из корня репозитория:
`php scripts/<имя>.php`.

## Миграция системы прав (`access-*`)

**Статус: подготовлено, но НЕ ВНЕДРЕНО.** Боевая таблица `tbl_access` и семантика
прав на сервере — прежние. Тулкит ниже написан и отлажен, но по инструкции ещё ни
разу не прогонялся на боевой базе. Внедрение — отдельное решение после ревью
снапшота и чистой сверки.

Смысл новой модели (`scripts/include/access-lib.php`):

- **open-канал**: по умолчанию доступ есть у ВСЕХ юзеров из `tbl_users`; записи в
  `tbl_access` — только исключения (9 = бан, 0 = ридонли, 2..5 = повышенные права).
- **private-канал**: дефолта нет, доступ только по явным записям (`role != 9`).
- Главный канал не выделяется, подчиняется общим правилам.

Порядок внедрения (каждый шаг печатает отчёт, менять что-то можно только после
чистой сверки):

```
php scripts/access-snapshot.php                          # 1. эталон старых прав -> scripts/out/*.json (только чтение)
php scripts/access-dedup.php                             # 2. отчёт о дублях пар (user, place); --fix — устранить
php scripts/access-migrate.php                           # 3. сборка tbl_access_new (боевую не трогает); --force — пересобрать
php scripts/access-verify.php scripts/out/<снапшот>.json # 4. сверка новой таблицы с эталоном; провал = exit 1
php scripts/access-swap.php swap                         # 5. атомарный RENAME боевой <-> новой, старая -> backup
php scripts/access-swap.php rollback                     # откат на backup, если что-то пошло не так
```

После `swap` все сессии гасятся (права кешируются в сессиях — юзеры перелогинятся).
JSON-снапшоты пишутся в `scripts/out/` (в git не попадает) — это эталон для сверки,
не удаляйте его до конца внедрения.

В docker-разработке те же скрипты запускаются в контейнере:
`docker compose exec web php scripts/access-snapshot.php` (см. `docker/README.md`).
