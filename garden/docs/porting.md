# Как это переносилось с SWF и как это проверять

Оригинал — [Free Falling Girl](https://www.arcadecabin.com/play/free_falling_girl.html). В
`assets-source/` лежит сам фильм (`free-falling-girl.swf`), выгруженный из него ActionScript
(`original-action-script.txt`), страница портала (`original-page.html`) и превью
(`portal-thumbnail.jpg`); в `frontend/tests/data/` — записи эталонных прогонов.

Порт держится на одном правиле: **числа берутся из SWF, а не подбираются на глаз**. Поэтому в
репозитории есть инструменты, которые достают эти числа из фильма, и записи прогонов, с которыми
порт сверяется.

## Разбор фильма

```bash
node tools/asdump.mjs assets-source/free-falling-girl.swf --out as.txt   # весь ActionScript
node tools/avm1-parse.mjs as.txt                                        # разбор байткода
node tools/tags.mjs assets-source/free-falling-girl.swf                  # теги, включая спрайты
node tools/guy.mjs assets-source/free-falling-girl.swf                   # DefineSprite с clip actions
node tools/guy-data.mjs                                                  # -> frontend/src/game/guy.generated.ts
node tools/extract.mjs assets-source/free-falling-girl.swf assets-source/swf-tags
```

`guy-data.mjs` — это и есть риг: частицы, связи, массы, ограничения и таблица привязки графики к
костям уезжают в `frontend/src/game/guy.generated.ts`, откуда их читает `vm/`. Из того же разбора берутся
константы мира (`gravity = 0.0011`, `fric = 0.9993`, шаг 20 мс) и размер сцены фильма — 550×400;
порт же играет в своей комнате 1000×740 (`frontend/src/game/stage.ts`), потому что в фильме куклу удерживали
шары, а без них стенами пришлось стать самому миру — его стены тоже порта: 728×414 внутри картинки
зала, с отступами 136 по бокам и 163 снизу, а четвёртая — потолок в 200 px над
верхом картины, где куклу встречают шары уже портовые (`ball.ts`). Кукла и весь её арт — киношного
размера: она падает в большем зале, а не становится больше сама. Там же в разборе — цвет фона
(`SetBackgroundColor` = `#d7e7f4`). Сам цвет порт не берёт: вокруг мира у него чёрное
(`BACKDROP_COLOR`, и та же заливка у страницы в `frontend/src/styles.css`), а мир закрашен его собственной
картинкой зала (`frontend/public/assets/bg.png`; см. §8 в `docs/assets.md`).

Разбор AVM1 — отдельное удовольствие: см. «Формат AVM1» в `README.md` (длина действия у опкодов
≥ `0x80`, `If = 0x9D`, `Call = 0x9E`, перевёрнутые пары половин double, обратный порядок аргументов
в стеке). Ошибка в любом из этих мест выглядит как «код странный, но работает».

## Эталонные прогоны

`tools/inject-trace.mjs` дописывает в копию фильма логгер: `--count` — счётчики вызовов методов,
`--constraints` — таблица связей, `--dump` — запись прогона в `frontend/tests/data/`. Дальше запись
проигрывается в Ruffle (см. ниже), а `frontend/tests/original-trace.test.ts` и
`frontend/tests/data/original-trace.txt` сверяют с ней порт.

Сверяется не всё одинаково строго: падение центра масс — строго, а отдельные частицы — с допуском
в пару юнитов, потому что угловой решатель сохраняет углы точно, а порядок обхода частиц в порту
всё-таки свой. Отсюда правило для правок: **сначала объясни расхождение, потом меняй допуск** —
эталон здесь вместо вкуса.

## Оригинал рядом с портом

```bash
npm i --no-save puppeteer @ruffle-rs/ruffle
node tools/ruffle-shot.mjs tmp-ruffle        # серия скриншотов оригинала
node tools/ruffle-compare.mjs                # оригинал и порт рядом, шары отключены
node tools/probe-patch.mjs 123 "old" "new"   # правка строки в SWF и запуск в Ruffle
node tools/probe-number.mjs 123 0.0011 0.001 # правка числа в SWF и запуск в Ruffle
```

`probe-*` — тяжёлая артиллерия для тех случаев, когда непонятно, исполняется ли вообще разобранный
код: правим одну строку или одно число в копии фильма и смотрим, изменилось ли поведение. Так
проверялись и `hackContraint`, и множители гравитации. `ruffle-compare.mjs` полезен и для графики:
он же показывает оригинал в масштабе сцены, то есть то, как выглядели те самые мягкие края частей.
Порт он при этом снимает в окне 860×652 — в нём его зал нарисован ровно 0.8 экранного
пикселя на world-пиксель, то есть в том же масштабе, в каком фильм рисует свою куклу; своего кольца
вокруг зала у порта нет (мир — это и есть картинка зала), так что сойтись масштабами — это выбрать
окно, — и на скорости 1: игра
стартует впятеро медленнее фильма (`INITIAL_SPEED`), а два падения сравнимы, только если падают
одинаково быстро. Выше уже сказано, почему числа силуэтов читаются только со стороны фильма.

## Слои и что куда писать

| Слой | Файлы | Правило |
| --- | --- | --- |
| порт движка | `frontend/src/game/vm/` | только то, что есть в SWF: Verlet, частицы, связи, ограничения, экстрактор |
| сцена | `frontend/src/game/stage.ts`, `world.ts`, `doll.ts`, `block.ts`, `rope.ts` | надстройка порта, чисел из SWF не требует (кроме рига и размеров мира) |
| рендер | `frontend/src/game/scene.ts` | PixiJS и скиннинг; сюда же — вся работа со спрайтами и камерой |
| ввод и цикл | `frontend/src/game/game.ts` | фиксированный шаг, захват мышью, роутинг кликов по инструментам |
| оболочка | `frontend/src/App.vue`, `frontend/src/styles.css` | тулбар, без игровой логики |

Физику движка правим, только если она расходится с записью оригинала. Всё, что хочется «улучшить»
(трение, устойчивость, красивое поведение верёвки), живёт в слое сцены — и с числами, у которых
есть объяснение в комментарии.

## Полная проверка перед коммитом

```bash
npm run build        # vue-tsc --noEmit + vite build
npm test             # vitest: риг, эталонный прогон, верёвка, блок
node tools/smoke.mjs # собранная игра в Chromium: физика, тулбар, персонажи, полоска портретов, скриншоты
```

`assets:prepare` добавляется к этому списку, если правили графику: запекание, затем `npm run build`
и смоук — стыки видно только на скриншотах (см. `docs/assets.md`).
